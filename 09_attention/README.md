# 第 09 课 · 注意力机制 — "按需取用"的记忆

> 🌐 配套互动网页：[09_attention.html](../pages/09_attention.html)（讲解精华 + 可玩 demo，无需任何安装）


> 物理视角：注意力解决的是**多体问题**——序列里每个 token 与其他所有 token
> 两两相互作用（$O(T^2)$），而不是 RNN 那种"只与邻居耦合的链式系统"。
> 两两相互作用 = 一个 $T\times T$ 的耦合矩阵 = 注意力矩阵。

## 1. 从 RNN 的痛点到注意力

上一课的三个痛点：顺序计算、长程依赖衰减、信息瓶颈。共同的根因：
**信息必须沿链一步步搬运**。

注意力的解法极端而优雅：**给每个位置发一张全表**——第 $t$ 个位置可以直接
读取任何 $t' \le t$ 位置的信息，路径长度 $O(1)$。而且这些"读取"可以
整批并行（一次矩阵乘法），GPU 满血。

## 2. Q · K · V：一次"软查询"

把序列的每个 token $x_t$（一个 $d$ 维向量）用三个学出来的矩阵投三次影：

$$q_t = W_Q x_t,\qquad k_{t'} = W_K x_{t'},\qquad v_{t'} = W_V x_{t'}$$

用一个数据库检索的类比（但它是**软**的）：

| 角色 | 数据库语言 | 直觉 |
|---|---|---|
| Query $q_t$ | 查询语句 | "我在找什么" |
| Key $k_{t'}$ | 索引/标签 | "我有什么可被找到" |
| Value $v_{t'}$ | 记录内容 | "找到我后实际带走的信息" |

第 $t$ 个位置对第 $t'$ 个位置的**相关性分数** = $q_t \cdot k_{t'}$（内积：
对齐越好分越高——你在向量检索里天天用）。全序列一起算就是矩阵乘法：

$$S = QK^T \quad\in\mathbb R^{T\times T}$$

## 3. 完整公式（逐个部件拆）

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

1. $S = QK^T$：相关性矩阵，$S_{tt'}$ = 第 $t$ 个位置对 $t'$ 的兴趣
2. $\div\sqrt{d_k}$：**别让 softmax 饱和**。若 $q,k$ 的分量独立零均值单位方差，
   则 $q\cdot k = \sum_i q_i k_i$ 的方差是 $d_k$（随机行走方差相加！）
   → 分数尺度随维度增大 → softmax 输出趋近 one-hot → 梯度死区。
   除以 $\sqrt{d_k}$ 把分数方差拉回 $O(1)$。
3. $\text{softmax}$ 沿 key 维归一化：每行变成一个概率分布 = "我的注意力分配"
4. $\cdot V$：按注意力权重加权平均所有 value → 每个位置的新表示 =
   "按相关性调制的上下文混合"

## 4. 因果掩码 (causal mask)：不许偷看答案

GPT 是自回归的：预测 $x_{t+1}$ 时只能用 $x_{\le t}$。但上面公式里 $S_{t, t+1}$
也存在——第 $t$ 个位置能"看见未来"，训练时就作弊了。

解法简单粗暴：把未来位置的分数设成 $-\infty$，softmax 后注意力恰好为 0：

$$S_{t,t'} \leftarrow S_{t,t'} \quad (t' \le t), \qquad -\infty \quad (t' > t)$$

**自检方法**（代码里有）：扰动最后一个 token，前面所有位置的输出必须**一个比特都不变**。
这个性质测试请写进你以后所有 GPT 代码。

## 5. Multi-Head：并行的多视角

一次注意力 = 一种"相关性视角"。与其做一个 $d$ 维大注意力，不如做 $H$ 个
$d_k = d/H$ 维的小注意力，各自学各自的 $W_Q^{(h)}, W_K^{(h)}, W_V^{(h)}$，
最后拼接（再过一次 $W_O$ 混合）：

```
x (B,T,d) → H 份 (B,T,d/H) → 各自 attention → 拼回 (B,T,d) → 输出投影
```

为什么有效？一个头可以盯"主谓关系"，另一个头盯"指代关系"，第三个盯"相邻重复"——
**多子空间并行检索**。通信带宽没变（还是 $d$），视角多了 $H$ 倍。

## 6. 复杂度与代价

- 时间/显存 $O(T^2)$：注意力矩阵是 $T\times T$。这就是"context length"成为
  卖点的原因（长上下文 = 平方级开销；FlashAttention 等优化的目标）
- 注意力本身**没有位置概念**——把输入 token 任意置换，若无掩码输出跟着置换。
  所以必须显式注入位置信息（第 10 课：位置 embedding）
